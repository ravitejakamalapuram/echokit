## 💡 What
Added `aria-label` and `title` attributes to various input elements (number fields and header string fields) within the mock details view (`renderDetail`).

## 🎯 Why
In the EchoKit UI, many form labels are rendered as `<div class="ek-label">` without a `for` attribute linking them to their corresponding `<input>`. This means screen readers cannot automatically announce the input's purpose. By adding explicit `aria-label` attributes, screen reader users get clear context. Adding the `title` attribute ensures mouse users also get helpful hover tooltips.

## 📸 Before/After
*   **Before:** `<input class="ek-input" type="number" ... />`
*   **After:** `<input class="ek-input" type="number" aria-label="HTTP Status Code" title="HTTP Status Code" ... />`

## ♿ Accessibility
*   **WCAG 2.1 (Level A) - 3.3.2 Labels or Instructions:** Forms now have explicitly associated labels via `aria-label`, ensuring screen reader users know the purpose of fields like latency, status code, max uses, and header key/values.
*   **Usability:** Tooltips via the `title` attribute improve context for mouse users.
