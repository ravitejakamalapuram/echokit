## 2025-02-17 - O(N²) Performance Bottleneck in Conflict Resolution
**Learning:** Filtering arrays during rendering by `.filter(x => x.hash === i.hash).length` to count conflicts within mapping loops such as `renderRow` creates an O(N²) performance bottleneck, slowing down UI rendering.
**Action:** Use a `WeakMap` cached mechanism to pre-compute counts using a `Map` the first time an array is passed, then return counts from the cache to achieve O(N) performance overall and O(1) inside loops.
## $(date +%Y-%m-%d) - O(N) Performance Bottleneck in Repeated URL Parsing
**Learning:** Instantiating `new URL()` inside tight loops during UI rendering (like `renderRow` or `groupByDomain`) is a severe performance bottleneck. Wrapping `new URL()` in a `try/catch` and returning fallback values on failure makes the object inherently safe but swallows errors, which breaks existing application assumptions if calling logic relies on specific fallbacks when URLs are truly invalid.
**Action:** Use a memoized `parseUrl()` utility that utilizes a bounded LRU cache (e.g., `Map`) for fast O(1) retrieval. Ensure that the cache does not mutate objects. Critically, to preserve existing contract shapes, `parseUrl()` must explicitly throw `new TypeError('Invalid URL')` when encountering falsy URLs so that outer try/catch blocks trigger their expected fallbacks correctly.
