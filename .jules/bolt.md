## 2025-02-17 - O(N²) Performance Bottleneck in Conflict Resolution
**Learning:** Filtering arrays during rendering by `.filter(x => x.hash === i.hash).length` to count conflicts within mapping loops such as `renderRow` creates an O(N²) performance bottleneck, slowing down UI rendering.
**Action:** Use a `WeakMap` cached mechanism to pre-compute counts using a `Map` the first time an array is passed, then return counts from the cache to achieve O(N) performance overall and O(1) inside loops.
## 2025-02-18 - Caching URL Object and Relative URL Resolution
**Learning:** Instantiating `new URL()` inside tight loops during UI rendering is a severe performance bottleneck. Caching parsed `URL` objects for performance (e.g., using `parseUrl`) provides significant rendering speedup. When refactoring URL parsing logic or using shared utilities like `prettyUrl` and `parseUrl` across files (e.g., in `extension/shared/app.js`), always pass a base URL (such as `location.href`) if the input URLs might be relative. `new URL(url)` will throw a TypeError for relative URLs without a base parameter. Additionally, never mutate the returned cached instances directly (like setting `u.search = ''`), as this causes cross-request data corruption.
**Action:** Use a `Map` cache with limit. Pass base url when `prettyUrl` is called from `app.js`. Avoid mutating the object reference that returns from the cache.
