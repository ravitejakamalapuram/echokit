## 2025-03-09 - [O(N²) rendering bottleneck avoided by caching filter counts]
**Learning:** Found a specific performance bottleneck in `extension/shared/app.js` and `extension/shared/interaction-helpers.js`. Using inline `.filter(x => x.hash === i.hash).length` inside mapping functions like `renderRow` over the `interactions` array creates O(N²) loops during rendering, significantly slowing down the UI as the number of network requests grows.
**Action:** When calculating frequencies or counts over large state arrays during rendering, always precompute the frequencies into a bounded `WeakMap` or `Map` dictionary (O(N)) beforehand, and do a quick `O(1)` lookup for each item during the render loop. This efficiently mitigates the O(N²) scaling issue while maintaining pure, functional UI rendering logic.
