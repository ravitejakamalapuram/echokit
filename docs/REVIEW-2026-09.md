# EchoKit — Full Review (2026-09)

Scope: APP-8, a deprioritized (P3) full review of product/UX/code quality/reliability. Scoped as a
focused pass, not a rewrite. No code was changed as part of this review; payment/licensing code was
read but not touched (a Gumroad migration is a separate, not-yet-started task).

Reviewed: `extension/background.js`, `extension/content.js`, `extension/injected.js`,
`extension/shared/*.js` (app.js, pro-status.js, matcher.js, store.js, sanitize.js, and others),
`extension/popup/`, `extension/onboarding/`, `extension/devtools/`, `tests/`, `worker/worker.js`,
`.appforge/permissions.yaml`, `manifest.json`, `package.json`, and the build/CI scripts.

## Bottom line

The core extension (recording, mocking, matcher, storage) is in solid shape: consistent
`sanitizeHTML()` discipline before every `innerHTML` write, a real SSRF-style allowlist on the
license endpoint, timeouts on every fetch, retry/backoff on IndexedDB open, and decent JSDoc. No
committed secrets, no `eval`/`new Function`, no obviously over-broad permissions relative to what's
declared in `.appforge/permissions.yaml`. Nothing here rises to "stop and fix now."

The two things worth the founder's attention are both about the **licensing path** — not because
the code is wrong, but because it's the one place where a subtle, already-acknowledged trade-off
carries real revenue risk, and it's also the one place with the least test coverage.

## Findings, prioritized

### 1. (Revenue risk, informational) License validation fails open, and the extension can force that path itself
`extension/background.js:236-276` (`isLicenseValid`): if the license worker is unreachable, any
string matching the *public, documented* key format (`XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX` or
`EK-PRO-|EK-YEAR-|EK-LTD-...` — the exact format is shown to the user in the error message at
`background.js:1408`) is accepted as a valid Pro license for up to 24h (the cache TTL), re-checked
only on the next cache expiry or restart. This is intentional and already documented in the code
(`background.js:265-274`, "SECURITY NOTE") as a deliberate uptime-over-strictness trade-off.

Worth flagging anyway: EchoKit itself holds `declarativeNetRequest` and `<all_urls>` permissions, so
a user (or a malicious fork of the extension) doesn't need to wait for an outage — blocking the
worker's domain via the extension's own DNR rules, or simply going offline, reliably forces the
fail-open branch on demand. Combined with `handleEchokitLicenseSet` (`background.js:1416-1424`)
also accepting a key locally whenever the remote check merely fails to respond (`remote.ok ===
false`, as opposed to explicitly rejecting), a correctly-shaped-but-never-purchased key plus a
blocked network call is enough to get permanent Pro. This is a known and intentional trade-off, not
a bug — flagging it so the founder can decide it's still the right call at the current revenue
stakes, and revisit if/when the Gumroad migration touches this path.

### 2. (Reliability gap) The riskiest licensing branch has zero test coverage
`tests/test-pro-status.js` thoroughly covers `extension/shared/pro-status.js`
(`computeProStatus`, `getPaywallConfig`, `recordInstall`) — that part is well tested. But the actual
license-key logic lives in `background.js` and is untested entirely: `validateLicenseKey` (format
gate), `validateLicenseRemote` (network call + timeout), `resolveLicenseEndpoint` (the SSRF
allowlist), and `isLicenseValid` (the cache + fail-open branch from finding #1). None of these are
exported or exercised by any test file. Given this is the one code path where a defect directly
costs money, it's the one place worth a unit test — even a couple of cases (`isLicenseValid` returns
`true` when the fetch throws; `resolveLicenseEndpoint` rejects a non-allowlisted stored endpoint)
would catch a future regression before it ships.

### 3. (Hygiene) `tests/` has five files that don't run and don't mean anything
None of these are wired into `npm test` or referenced by CI, so they're pure bit-rot that misleads
anyone (human or agent) who assumes "there's a tests folder, so it's covered":
- `tests/test_validation.js` and `tests/test_imports.js` import `extension/shared/validation.js`
  and `extension/shared/logger.js` — **neither file exists anymore**. Both fail immediately with
  `ERR_MODULE_NOT_FOUND`.
- `tests/test-perf-delete.js` also fails to resolve a module import.
- `tests/consistency/single-source-enforcement.test.js` calls `describe()` (Jest/Mocha syntax) but
  has no test runner wired to it — running it with plain `node` throws `ReferenceError: describe is
  not defined`.
- `tests/integration/ui-componentization.test.js` actually runs, but its own assertion is stale:
  it expects `formatDuration(0)` to return `'—'`, while the real implementation
  (`extension/shared/interaction-helpers.js:78-81`) deliberately returns `'0ms'` for a genuine
  sub-millisecond response (only `null`/`undefined` should render as `'—'`). The *code* is correct;
  the *test* wasn't updated after that behavior was intentionally changed.

None of this affects the shipped extension — `npm test` (the 6 real suites + CLI tests, 20/20
passing) is what CI actually runs, and it's solid. But this is cheap to clean up: delete the four
broken files, and fix or delete the one stale assertion.

### 4. (Minor, ships-in-prod) A dev diagnostic page ships inside the Chrome Web Store package
`extension/popup/test-popup.html` + `extension/popup/diagnostic.js` are a scratch diagnostic page
(pings the background worker, loads `app.js`, prints pass/fail steps). `scripts/build-store-zip.sh`
only excludes `*.test.js`, `*.spec.js`, and `tests/*` — an `.html` file living in `popup/` isn't
caught, so it's zipped into every store release and reachable at a guessable
`chrome-extension://<id>/popup/test-popup.html` URL in production. The page itself is harmless (no
secrets, no privileged action a user couldn't already trigger), but it's unshipped dev debris in a
public artifact. Easy fix later: move it under `tests/` (already excluded) or add an explicit
`-x 'popup/test-popup.html' -x 'popup/diagnostic.js'` to the zip command.

## Things that are fine (said plainly, not manufactured)

- **XSS discipline**: every one of the 12 `innerHTML` assignments in `shared/*.js` goes through
  `sanitizeHTML()` (DOM-based, strips `<script>`/`<iframe>`/`<object>`/event handlers/
  `javascript:`/`data:`/`vbscript:` URLs) — no inconsistent raw-HTML injection found anywhere.
- **SSRF guard on the license endpoint**: `LICENSE_ENDPOINT_ALLOWLIST` in `background.js` means a
  compromised/edited `chrome.storage.sync` value can't redirect license checks to an attacker
  endpoint. Good defensive design for a permission (`<all_urls>` + `cookies` + `scripting`) this broad.
- **Permissions match declared reasons**: every entry in `.appforge/permissions.yaml` maps to a real,
  identifiable feature (tabs → attach recordings to the right origin; scripting → localStorage
  copy/paste utility; cookies → cookie copy/paste utility; clipboardRead/Write → the same
  utilities). Nothing requested that isn't used.
- **No secrets committed.** `worker/.wrangler/cache/wrangler-account.json` (contains a Cloudflare
  account ID) is untracked and covered by `.gitignore` (`.wrangler/`) — confirmed via `git status`
  and `git log`; it has never been committed.
- **Storage/network error handling**: consistent try/catch around `chrome.storage.*` calls and
  fetches, with explicit timeouts (`AbortController`, 5s) on both the license-validate and
  paywall-config network calls, and exponential-backoff retry on IndexedDB open in `store.js`.
- **Onboarding** (`onboarding/welcome.js`/`.html`) is short and clear: pin instructions, one-click
  demo tab open with a `window.open` fallback if `chrome.tabs.create` fails, clipboard copy with a
  "Select & copy" fallback if `navigator.clipboard` throws, and a lightweight self-tracked checklist.
  No dead ends or unclear copy found.
